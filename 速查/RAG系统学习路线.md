# RAG 系统学习路线（8 步地图 × 本项目进度）

> 来源：你从 ChatGPT 拿到的 8 步建议 + 本项目实际阶段安排。
> 用途：知道"**现在学哪、以后学哪、每步怎么算学会**"，避免一时兴奋把阶段 5 拖成"学框架"。
> 原则（和那份建议一致）：**先理解底层原理 → 再学框架 → 最后独立实现一个简单 RAG**。
> 我们正在做的就是第三步，只是选了"最小可用版"。

## 1. 两条腿走路（怎么安排时间）

- **主线（占 80% 时间）**：阶段 5 手写最小 RAG——今天就做「六步法第 1 步：写 3~5 行用法」；
- **副线（占 20%，每天 ≤30 分钟）**：B站/文章只用来**建概念地图**，只记"和我们项目有什么不同"；
- **不做**：不在阶段 5 装 LangChain / LlamaIndex / Chroma；不跟着视频敲一遍代码（学习方法反模式：抄一遍的"我会了"错觉最强）。

## 2. 七个概念。"现在该怎么理解"

| 概念 | 现在（阶段 5）你能对应到的东西 | 以后（阶段 8）再深入 |
|---|---|---|
| `Chunking` | 我们的"段落"：按空行切段，标题拼到段前 | 重叠切分（overlap）、递归切分、按语义切分 |
| `Embedding` | 我们用的是 **bigram 字面对齐**；embedding 是"意思对齐" | 调 embedding 接口、比余弦相似度 |
| `Vector Database` | 我们现在把 chunk 放内存 list；向量库 = "+索引 +快速找相似向量"的存储 | 向量库选型、索引（HNSW）、元数据过滤 |
| `Similarity Search` | 我们的分数 = 重合 bigram 数 ÷ query bigram 数 | 向量版：余弦相似度 / 内积 |
| `Retriever` | `search()` 就是最朴素的 retriever | 混合检索（关键词 + 向量）、多路召回 |
| `Reranker` | 我们没有（所以"top1 不一定最准"） | 检索完再排一次序（用更贵的模型二次打分） |
| `Context` | 我们没接 LLM；阶段 3 的 `messages` 就是上下文载体 | 上下文窗口管理、压缩、引用出处 |

## 3. 那 6 个问题，什么时候能答

| 问题（来自你的 ChatGPT 对话） | 阶段 5 学完 | 阶段 8 |
|---|---|---|
| 为什么不能直接把整个 PDF 塞进 Prompt？ | ✅ 能答（上下文窗口 / 成本 / 噪音） | — |
| Embedding 和普通文本有什么区别？ | 🕓 能说出直觉，动手要等以后 | ✅ |

| 向量数据库究竟存储了什么？ | 🕓 一句话能说，没动手 | ✅ |
| RAG 为什么有时候会检索到错误内容？ | ✅ 能答（bigram 不懂语义 / 关键词不匹配 / 标题没拼 / 切分不当） | 再看失败模式清单 |

> 自测方法：阶段 5 收尾时把这 6 个问题重答一遍，标 ✅ 的必须答满，🕓 的能说出"它解决什么问题"即可。

## 4. 阶段 5 结束后可选的三个加餐（不是现在做）

1. **embedding 对比实验**：调一次 embedding 接口，对两句近义句（"怎么避免内存泄漏" vs "malloc 之后要 free"）算余弦相似度，再和 bigram 分数对比——直观看到"字面 vs 语义"；
2. **最小向量库**：用 JSON 存"文本 + 向量"，手写余弦相似度，替换 `search()`（几十行，不装包）；
3. **rerank 实验**：对 bigram 的 top-5 再用二次打分（例如包含 query 完整词的加分），看 top1 是否变准。

三个加餐都要写成 `速查/实验_xxx_分段.py`，**先在阶段 5 结业之后再做**。

## 5. B 站视频怎么挑（30 分钟原则）

- 搜：`RAG 原理` / `RAG 通俗` / `Chunking 原理` / `Embedding 通俗`；
- 避开：`LangChain RAG 实战` / `Chroma 实战` / `向量数据库实战`（阶段 8 再看）；
- 判断标准：**讲"为什么"的 > 讲"怎么调包"的**；能画出流程图；提到失败模式；
- 每天 ≤30 分钟，看完写 3 条"和我们项目的差异"（贴给教练，比"看完了"有用）。

## 6. 每一步的验收问题（自检表）

1. **原理**：RAG 的两个阶段？为什么不能全塞 prompt？→ 能用自己的话讲 3 句
2. **加载**：怎么把目录里的 md/txt 变成 `Chunk` 列表？坏字节怎么办？
3. **Chunking**：为什么按空行切？标题为什么要拼到段落前？chunk 太大/太小各有什么问题？
4. **Embedding**：向量是什么？"意思相近 → 向量相近"在解决什么？
5. **向量库**：它存的到底是什么？为什么需要它（不就是一个 list 吗）？
6. **Retrieval**：相似度怎么算？`top_k` 为什么不能太大/太小？
7. **Prompt+LLM**：检索结果以什么形式进入提示词？模型为什么能"基于资料"回答？
8. **优化**：rerank 解决什么？怎么判断一次 RAG 改好了？（评估）
