## 1. 通用词根（跨阶段，任何阶段都可能出现）

Python 的命名基本是"小写 + 下划线"（叫 snake_case，蛇形命名）。很多名字就是两三个词根拼起来。

| 词根 | 中文 | 例子 |
|---|---|---|
| `get` / `set` | 取 / 设 | `get(task_id)` 按编号取一条；`setdefault` 没有才设 |
| `load` / `save` | 加载（文件→内存）/ 保存（内存→文件） | `_load()` / `_save()` |
| `read` / `write` | 读 / 写（直接对文本） | `read_text()` / `write_text()` |
| `parse` | 解析：把字符串拆成结构 | `parse_due()` |
| `normalize` | 归一化：统一成一种标准格式 | `_normalize_due()` |
| `create` | 创建 | `create_client()` |
| `add` / `remove` | 添加 / 移除 | `add()` / `list.remove()` |
| `include` | 包含 | `include_done`（是否包含已完成的） |
| `done` | 已完成 | `done` 字段 |
| `default` | 默认值 | `default_factory` |
| `factory` | 工厂：专门"造东西"的函数 | `default_factory` = 造默认值的函数 |
| `store` | 存储 / 仓库（不是"商店"） | `TaskStore` |
| `due` | 到期 / 截止日 | `due="2026-10-20"` |
| `days_left` | 剩余天数 | `days_left()` |
| `describe` | 描述：转成一行文字 | `describe()` |
| `upcoming` | 即将到来的 | `upcoming(7)` |
| `provider` | 服务提供方（哪家模型厂商） | `provider="deepseek"` |
| `client` | 客户端：帮你发请求的对象（不是"顾客"） | `client.chat...` |
| `fake` | 假的 / 测试替身 | `FakeClient` |
| `completion` | **补全 / 续写**（不是"完成"） | `completions.create(...)` |
| `response` | 响应：服务器返回的东西 | `_response()` |
| `preset` | 预设（pre 预先 + set 设定） | `preset = PROVIDERS[...]` |
| `script` | 剧本：预先写好的台词 | `script=["第一句"]` |
| `calls` | 调用记录（每次请求的留档） | `client.calls` |
| `env` | environment 的缩写：环境（这里指环境变量） | `os.environ` |
| `dotenv` | ".env 文件"的读法（dot + env） | `load_dotenv` |
| `api key` | 接口密钥（你的账号凭证） | `STUDYMATE_API_KEY` |
| `base_url` | 基础网址（接口的根地址） | `https://api.deepseek.com` |
| `model` | 模型 | `deepseek-chat` |
| `id` | 编号 / 标识 | `task_id` |
| `kwargs` | keyword arguments 的缩写，读作 "K-words"：任意关键字参数 | `**kwargs` |
| `args` | arguments 的缩写：任意位置参数 | `*args` |
| `asdict` | as dict，"当作字典来" | `asdict(task)` |

### 4.1 核心名词

| 名字 | 中文 | 怎么理解 / 为什么叫这个 |
|---|---|---|
| `tool` | 工具 | 模型"能调用的一个函数"。对模型来说它是"本事"，对我们来说就是普通 Python 函数 |
| `tool call` | 工具调用 | 模型不直接做事，而是**回一句话请求**我们去执行；不是"打电话" |
| `tool_call_id` | 工具调用编号 | 每次调用一个编号，工具结果靠它对应回"这是回你第几个请求" |

| `system prompt` | 系统提示词 | prompt = 提示词；system = 系统层，每次请求都放在最前面，用来定身份和规矩 |
| `hallucination` | 幻觉 | 模型一本正经地编造事实；工具调用就是用来压它的 |
| `agent` | 智能体 | 这里指"会循环思考 + 会调工具"的程序，不是"代理人" |

### 4.3 两个容易混的词

| 词 | 中文 | 区别 |
|---|---|---|
| `parameter`（形参） | 函数定义里的参数 | `def add(a: int, b: int)` 里的 a、b |
| `argument`（实参） | 调用时真正传进去的值 | 模型给的 `{"a": 2, "b": 3}` |

> 记住：**定义时叫 parameter，调用时叫 argument**；日常口语里中文都叫"参数"，看英文时才知道在说哪一边。

### 5.1 测试基础

| 名字 | 中文 | 怎么理解 / 为什么叫这个 |
|---|---|---|
| `test` | 测试 | 自动验收：不用人眼看输出，跑一下就知道对没对 |
| `unittest` | 单元测试框架 | 标准库自带、零依赖；unit = 被测的"最小单元"（一个函数/一个类） |
| `TestCase` | 测试用例类 | 继承它，框架才会收集里面 `test_*` 开头的方法并自动跑 |
| `test case` | 测试用例 | 一个 `def test_xxx(self)` 方法 = 一条测试 |
| `test suite` | 测试套件 | 一堆测试打包一起跑 |
| `test runner` | 测试运行器 | 负责"找测试 → 跑 → 报结果"（PyCharm 右键 Run 背后就是它） |
| `setUp` | 测试前准备 | 每个测试方法**前**自动调用一次 |
| `tearDown` | 测试后清理 | 每个测试方法**后**自动调用一次（测试失败也会调） |
| `fixture` | 夹具 | 测试用的固定数据/环境：`build_registry()` 造的那两个工具 |
| `temporary directory` | 临时目录 | `tempfile.TemporaryDirectory()`：建一个空目录，`cleanup()` 删掉 |
| `isolation` | 隔离 | 每个测试互不影响：各用各的临时目录、各用各的假客户端 |
| `pollution` | 污染 | 上一个测试的残留影响下一个（日志 level 没恢复、handler 没摘就是它） |
| `assert` | 断言 | "我断定这件事为真"；不成立就 FAIL（不是抛异常，是这条测试记红） |
| `expected` / `actual` | 期望值 / 实际值 | 断言失败时报告里 `实际 != 期望` 的两半 |
| `FAIL` / `ERROR` | 失败 / 错误 | FAIL = 断言执行了但不成立；ERROR = 测试半路抛异常（没走到断言） |
| `regression` | 回归 | 改了新东西，**旧测试必须仍然绿**：`阶段3` 的 28 条就是回归测试 |
| `side effect` | 副作用 | 函数除返回值之外对世界做的改动（`execute("add_task")` 真的往 store 里写了一条） |
| `fake` | 假 / 替身 | 形状和真的完全一样，只是不干真事（`FakeToolClient`） |
| `stub` | 桩 | 只提供固定返回、不关心"被怎么调"的替身 |
| `mock` | 模拟对象 | 能记录"被调了几次、传了什么参数"的替身（`client.calls` 干的就是这事） |
| `coverage` | 覆盖率 | 测试跑到了多少代码行；我们只用概念，没接工具 |
| `sys.path` | 模块搜索路径 | `import` 时去哪里找模块；测试文件要把本目录插进去才能 `import support` |
| `cwd` | 当前工作目录 | 相对路径的基准；PyCharm 右键 Run 时它**不一定**是测试文件所在目录 |

### 5.2 断言方法小抄

| 名字 | 中文 | 用在哪 |
|---|---|---|
| `assertEqual(a, b)` | 断言相等 | 返回值、描述字符串这类精确比较 |
| `assertIn(x, 容器)` | 断言包含 | 日志全文里有没有某段文字 |
| `assertTrue(x)` | 断言为真 | 只关心"非空/成立"：描述非空 |
| `assertIsInstance(x, str)` | 断言类型 | `execute()` 必须返回字符串 |
| `assertIsNone(x)` | 断言是 None | 空注册表传 `tools=None` |
| `assertRaises(异常)` | 断言会抛异常 | 用 `with self.assertRaises(TaskError):` 包住 |
| `msg=` 参数 | 失败时的附加说明 | 循环里断言时，指明"是 a 还是 b 坏了" |

> 我们项目的顺序约定：**第一个参数放实际值，第二个放期望值**（`assertEqual(result, "5")`），
> 这样报错 `'你好，同学' != '你好,同学'` 读起来就是"实际 != 期望"。

### 5.3 日志（长版见 `速查/日志与logging速查.md`）

| 名字 | 中文 | 怎么理解 / 为什么叫这个 |
|---|---|---|
| `logging` | 日志模块 | 标准库；程序运行过程的"行车记录仪" |
| `log` / `logger` | 日志器 | 代码里 `log = logging.getLogger(__name__)` 拿到的对象，自己定名字（通常模块名） |
| `root logger` | 根日志器 | 所有 logger 的祖先（`logging.getLogger()` 不传名字就是它）；所有日志最后冒泡到这 |
| `handler` | 处理器 | handle = 处理；决定日志**写去哪**：`StreamHandler`(屏幕) / `FileHandler`(文件) / 内存流 |
| `formatter` | 格式器 | 决定**每行长什么样**：`%(levelname)s %(name)s %(message)s` |
| `level` | 级别 | DEBUG(10) < INFO(20) < WARNING(30) < ERROR(40) < CRITICAL(50) |
| `effective level` | 有效级别 | logger 自己没设级别时，向上继承父级直到 root（root 默认 WARNING） |
| `propagate` | 冒泡 / 向上传递 | 默认 `True`：子 logger 的日志会传给父 logger 的 handler 写出去 |
| `traceback` | 调用栈 | 出错时的"路过路线"；`log.exception` 会自动带上它 |
| `exception` vs `error` | 带栈 vs 不带栈 | `log.exception()` = `log.error(..., exc_info=True)`，必须在 `except` 块里用 |
| `capture` | 捕获 | `capture_logs`：把日志"抓"进临时文件，让测试能读 |
| `redirect` | 重定向 | 换出口：日志从屏幕改到文件，业务代码一行不改 |
| `stream` / `StringIO` | 流 / 内存字符串流 | 测试里用它当"假文件"接日志 |
| `buffer` / `flush` | 缓冲区 / 冲刷 | 不 `close()`/`flush()`，最后几行可能还没落盘（读到的文件是空的） |
| `context manager` | 上下文管理器 | `with ...:` 背后那个对象；`__enter__` 准备、`__exit__` 收尾（异常也收） |
| `RAII` | 资源获取即初始化 | C++ 的叫法：构造时申请资源、析构时释放；Python 的 `with` 就是它的等价物 |

### 5.4 判卷（测试质量怎么证明）

| 名字 | 中文 | 怎么理解 |
|---|---|---|
| `mutation testing` | 变异测试（我平时叫"判卷"） | 故意把实现改坏一处，跑测试，看**对应的**测试红不红 |
| `mutant` | 变异体 | 被改坏的那一份实现 |
| `kill` | 杀死 | 测试把变异体抓红了 = kill 成功；还是绿 = 测试没抓到，是无效测试 |
| `false green` | 假绿 | 断言太松（只断 `"add"` 不断参数），实现坏了也照样绿 |

### 5.5 三组容易混的词

| 对比 | 区别一句话 |
|---|---|
| `ERROR` vs `FAIL` | ERROR 是半路抛异常（看 traceback 最后一行）；FAIL 是断言不成立（看 `实际 != 期望`） |
| `logger` vs `handler` | logger 决定"要不要说"（级别门槛），handler 决定"说给谁听"（屏幕/文件） |
| `fake` vs `stub` vs `mock` | fake = 形状一样的假货；stub = 只会固定回答；mock = 还会记账（被调几次、传了什么） |

### 6.1 RAG 与检索核心名词

| 名字 | 中文 | 拆词 / 记忆点 |
|---|---|---|
| `RAG` | 检索增强生成 | Retrieval-Augmented Generation 的缩写：先**检索**资料，再**增强**提示词，再让模型**生成** |
| `retrieval` | 检索 | retrieve（取回）+ -al（名词）：从资料里"取回"相关片段 |
| `augmented` | 增强的 | augment = 增大/加强；"给提示词补充资料" |
| `generation` | 生成 | generate = 产生；模型写回答那一步 |
| `query` | 查询词 | 用户的问题被当成检索条件；不是"数据库查询语句" |
| `corpus` | 语料库 | 你的一堆文档（这里是 `notes/` 目录） |
| `chunk` | 片段 | 检索的最小单位：一段话。**不是"大块"**，这里专指切好的段落 |
| `paragraph` | 段落 | 按空行切出来的那一块 |
| `heading` | 标题 | Markdown 的 `## 指针`；要拼到段落开头 |
| `bigram` | 二元组 | bi（两个）+ gram（字/记号）：相邻两个字的组合，如"指针" |
| `token` | 词元 | 模型眼里的最小单位；中文没有空格，切 token 是另一门学问 |
| `overlap` | 重合 | 两个集合都有的元素（`len(q & c)`） |
| `score` | 分数 | 相关度得分：本阶段 = 重合数 ÷ query bigram 数 |
| `rank` | 排名 / 排序 | `sorted(..., key=..., reverse=True)` |
| `top_k` | 取前 k 个 | k 是"取几条"的通用符号 |
| `hit` | 命中 | 检索到的一条结果（`hits` 是结果列表） |
| `match` | 匹配 | query 和片段"对上了" |
| `semantic search` | 语义检索 | 按"意思"找；bigram 是按"字面"找，本阶段只做字面 |
| `embedding` | 嵌入（向量） | 把文字变成一串数字；意思相近 → 向量相近（阶段 5 不写，知道概念） |
| `cosine similarity` | 余弦相似度 | 比较两个向量方向是否接近；1 = 完全同向 |
| `cache` | 缓存 | 算过一次就存起来（向量很贵，真实项目必须缓存） |

### 6.2 代码里的名字

| 名字 | 中文 | 出现在哪 / 干什么 |
|---|---|---|
| `NOTES_DIR` / `notes_dir` | 笔记目录 | 检索的"语料库"位置 |
| `Chunk` | 检索片段（数据类） | 字段：`file`（来源文件）、`text`（正文，带标题）、`score`（分数） |
| `load_chunks` | 加载片段 | 遍历目录 → 切段 → 生成 `Chunk` 列表 |
| `list_files` | 列文件 | 返回笔记文件名列表（给模型看"有哪些笔记"） |
| `read_file` | 读文件 | 读单篇全文；**必须防路径逃逸** |
| `max_chars` | 最大字符数 | 读文件时截断，防止把超长笔记整个塞给模型 |
| `rglob` | 递归匹配 | `notes_dir.rglob("*")`：连子目录一起列 |
| `suffix` | 后缀 | `path.suffix` → `.md` / `.txt` |
| `relative_to` | 相对路径 | `path.relative_to(notes_dir)` → 返回给模型看的是短路径 |
| `as_posix` | 转成 / 分隔 | 把 Windows 的 `\` 变成 `/`，跨平台 |
| `resolve` | 解析成真实路径 | 把 `..`、软链接都算掉；**判断安全之前必须做** |
| `parents` | 所有祖先目录 | `base in target.parents` 用来判断"目标还在目录里吗" |
| `errors="ignore"` | 忽略坏字节 | `read_text(..., errors="ignore")`：文件里有坏字节也不崩 |
| `re.split(r"\n\s*\n", text)` | 按空行切 | 一个空行 = 一个新段落 |
| `parents` / `path traversal` | 路径穿越 | 见 6.3 |

### 6.3 五组容易混的词

| 对比 | 区别一句话 |
|---|---|
| `retrieval` vs `generation` | 检索 = 找资料（本阶段做）；生成 = 写回答（阶段 3 的模型做） |
| `bigram` vs `token` | bigram 是"两个字的组合"（我们手算的）；token 是"模型切词的单位"（模型内部的事） |
| `chunk` vs `paragraph` | 本阶段的 chunk 就是一个段落（带标题）；换成别的切法后 chunk 可以不是段落 |
| `top_k` vs `k` | 同一个 k：`top_k=3` 就是"取前 3 条"，k 是通用符号 |
| `path traversal` vs `path escape` | 同一个东西的两种叫法：用 `../` 逃出允许目录（中文叫"路径穿越/路径逃逸"） |

### 6.4 安全名词（阶段 5 唯一的安全点）

| 名字 | 中文 | 为什么在这里出现 |
|---|---|---|
| `path traversal` | 路径穿越 | 模型给的 `name` 不可信，可能是 `../.env` |
| `untrusted input` | 不可信输入 | 来自模型/用户的字符串一律先校验再用 |
| `sanitize` | 清洗 / 校验 | 本阶段不是"删字符"，而是"解析后判断是否仍在目录内" |

## 7. 跨阶段：最容易误解的 12 个

| 名字 | 你以为 | 实际 | 首见 |
|---|---|---|---|
| `completion` | 完成 | **补全/续写**——模型的本质是"接着往下写" | 阶段 2 |
| `client` | 顾客 | **客户端对象**（发请求的那一端） | 阶段 2 |
| `store` | 商店 | **存储 / 仓库** | 阶段 1 |
| `fake` | 假的、没用 | **测试替身**：形状和真的完全一样 | 阶段 2 |
| `provider` | 提供者（人） | **服务商标识**（`deepseek` / `fake`） | 阶段 2 |
| `preset` | 预置？ | pre 预先 + set 设定 = **预先配好的一套值** | 阶段 2 |
| `describe` | 描述（动作） | **转成人类可读的一行文字** | 阶段 1 |
| `due` | 应有的 | **到期 / 截止**（`deadline` 才是"最后期限"） | 阶段 1 |
| `upcoming` | 上来的 | up（来临）+ coming（正在来）= **即将到期** | 阶段 1 |
| `dumps` / `dump` | 一样 | `dumps` 加 s = 返回**字符串**；`dump` 写进**文件对象** | 阶段 1 |
| `_load` 的下划线 | 装饰？ | **单下划线 = 内部使用**，约定"别从外面直接调" | 阶段 1 |
| `__init__` 双下划线 | 只是名字 | **协议方法**：Python 会自动调用（`Config(...)` 就调它） | 通用 |

## 8. 读代码时的三步

1. **定位阶段**：这段代码在哪个 `阶段N_` 目录？→ 查第 0 节的表，跳到对应节。
2. **拆词根**：还看不懂就回第 1 节拆（`load_dotenv` = load + dotenv = "加载 .env 文件"）。
3. **还不行就问**——问的时候把那一行贴出来，比描述"那个函数"更快。

## 9. 我以后怎么给新词

新英文名字第一次出现时，我会写成：

> `preset`（**预设**：pre 预先 + set 设定，指"预先配好的一套默认值"）

然后再用它。缩写（如 `env`、`kwargs`、`api`、`JSON`）会展开全拼一次。
每开一个新阶段，收尾时把该阶段的新词补进对应的第 N 节。
