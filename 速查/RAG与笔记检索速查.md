## 0. 一句话：RAG 是什么

**RAG = Retrieval-Augmented Generation，检索增强生成**（拆词见 §1）。

模型有两个硬限制：① 它没见过你的课堂笔记；② 它一次读不完你所有资料。
RAG 的办法是：**先从你的资料里检索出最相关的几段，再连同问题一起交给模型生成回答**。

```
用户问题 ──┐
           ├─ 检索（本阶段）：从 notes/ 里找出最相关的 3 段
笔记目录 ──┘        │
                    ▼
       把「相关段落 + 问题」拼进提示词 ──→ 模型生成回答（阶段 3 的 agent）
```

**agent 主动检索**（模型自己决定要不要调 `search_notes`）比"每次强制检索"更灵活——所以参考版把它做成一个工具。

## 2. 中文检索的难题：没有空格怎么切

英文按空格切词，中文不能：

```
"数组和指针"  → 切成什么？
  按字：数 / 组 / 和 / 指 / 针          ← 太碎，没有意义
  按词：数组 / 和 / 指针                ← 需要分词词典（要装包）
  按二元组：数组 / 组和 / 和指 / 指针    ← 不用词典，够用
```

**bigram（字符二元组）**：把文本里相邻两个字两两组合成一个集合：

```
"数组指针" → {"数组", "组指", "指针"}         （4 个字 → 3 个 bigram）
"数组和指针" → {"数组", "组和", "和指", "指针"}（5 个字 → 4 个）
```

- 优点：零依赖、对"关键词明确"的问题很灵、实现就三行；
- 缺点：**不懂语义**。问"怎么避免内存泄漏"，笔记写"malloc 之后必须 free"，两者几乎没有相同的字 → 搜不到。这时候才需要 embedding（语义检索）。

## 3. 打分：重合比例

```
query 的 bigram 集合 Q，某个段落的 bigram 集合 C
分数 = |Q ∩ C| / |Q|          ← "query 里有多大比例的 bigram 在段落里出现过"
```

例：`Q = {"数组","组和","和指","指针"}`（4 个），段落里有 `{"数组","指针"}` 两个 → 分数 = 2/4 = 0.5。

为什么**除以 |Q|** 而不是别的：
- 除以 |Q|：分数 ∈ [0,1]，表示"query 被覆盖了多少"，查询越短越容易被整段命中（`"指针"` 常常 1.0）；
- 除以并集大小（Jaccard）：短段落会被过度偏好——段落越短越容易 1.0，排序会失真。

> 所以本阶段用 `1.0 = query 的 bigram 全在这个段落里` 来理解分数最直观。

## 4. 切段落：为什么按空行、为什么拼标题

```python
re.split(r"\n\s*\n", 全文)     # 空行（含只有空格的行）切段
```

- Markdown 里**一个空行 = 一个新段落**；
- 标题行（`## 指针`）本身不是内容，但它是"这段在讲什么"的重要线索。如果标题单独成段：
  - 搜"指针"时，标题能命中，但它没有正文，答非所问；
  - 正文段落里没有"指针"二字（可能写"它保存地址"），反而搜不到。
- 所以参考版的做法：**记住最近的标题，拼到后面每段的开头**（`指针：数组名在…`）。这样两种查询都能命中。

## 5. 路径安全：`read_file` 为什么必须有防护

`read_file(notes_dir, name)` 里的 `name` 来自模型（不可信！）。模型可能传：

```
"../.env"            → 读到你的 API Key
"../../系统文件"     → 读到笔记目录外的东西
```

正确做法（**先解析、再判断祖先**）：

```python
base = Path(notes_dir).resolve()          # 笔记目录的绝对路径
target = (base / name).resolve()          # 带 .. 也一起解析掉
if base not in target.parents:            # 目标必须仍在 base 下面
    raise ValueError("只能读取笔记目录里的文件")
```

- `.resolve()` 会把 `..`、软链接都算成真实路径——**先解析再判断**才靠得住；
- 判断用 `base in target.parents`（target 的所有祖先里有 base）而不是字符串 `startswith`（`/notes_evil` 会被 startswith 骗过）；
- 读不到 → `FileNotFoundError`，别返回空字符串（空字符串会让模型以为"文件是空的"）。

C 类比：`fopen` 之前不检查 `..`，别人就能让你打开任意文件——这是路径穿越漏洞的经典形态。

## 6. 文件遍历小抄（`pathlib`）

| 想做什么 | 写法 | 注意 |
|---|---|---|
| 递归列出所有文件 | `notes_dir.rglob("*")` | 返回生成器，记得 `sorted()` 才有稳定顺序 |
| 判断后缀 | `path.suffix.lower() in {".md", ".txt"}` | `.MD` 也要收，所以 `lower()` |
| 判断是文件 | `path.is_file()` | `rglob` 也会返回目录 |
| 相对路径（用于返回给模型） | `path.relative_to(notes_dir).as_posix()` | `as_posix()` 把 `\` 变 `/`，跨平台 |
| 读文本 | `path.read_text(encoding="utf-8", errors="ignore")` | `errors="ignore"`：坏字节不崩 |
| 路径存在 | `notes_dir.exists()` | 不存在时返回 `[]` 而不是抛异常 |
| 转绝对路径 | `Path(x).resolve()` | 路径安全判定前必须做 |

## 8. 六个坑

1. **标题处理**：不拼标题 → 搜"指针"命中标题行、正文命中不了；拼了 → 检索质量明显变好。这是本阶段最"看不见"的一个点。
2. **分数必须除以 |Q|**：除以并集大小（Jaccard）会让超短段落霸榜。
3. **空 query**：`_bigrams("")` 是空集合，`|Q| = 0` 会 **ZeroDivisionError**——必须先判断空集合直接返回 `[]`。
4. **单字 query**：`_bigrams("针")` 只返回 `{"针"}`，而段落 bigram 都是两字，几乎不可能命中——这是 bigram 的已知局限，测试里只要求"不崩"。
5. **路径逃逸**：`.resolve()` + `parents` 判断，别用字符串前缀比较。
6. **排序稳定性**：分数并列时顺序由遍历顺序决定——测试不要断言"并列时的名次"，只断言"第一名是谁"。
